# Say the word

אפליקציית תרגול מילים באנגלית. הזיהוי רץ במכשיר, בלי שרת ובלי אינטרנט.

האפליקציה נבנתה ב-Google AI Studio, אבל היא לא קוראת ל-Gemini ולא לשום
שירות חיצוני. אין מפתח API, אין קריאת רשת אחת בזמן ריצה, ו-`.env.example`
ריק בכוונה. כל מה שצריך כדי להריץ אותה יושב בריפו הזה.

## העלאה לאוויר

יש שני מסלולים, והם לא שקולים.

### GitHub Pages — המסלול שבשבילו האפליקציה נבנתה

הקבצים כבר בריפו. מה שנשאר זה להדליק את Pages פעם אחת:

Settings → Pages → Source: **Deploy from a branch** → Branch: **main**, תיקייה **/ (root)** → Save.

אחרי דקה־שתיים האתר עולה בכתובת `https://USER.github.io/REPO/`.
מכאן כל דחיפה ל-`main` עולה לאוויר לבד.

את `index.html` אפשר לערוך ישירות באתר GitHub — הוא קטן ולא נוגע
במגבלת ה-25MB של העלאה דרך הדפדפן. את `model.tar.gz` (29MB) לא ניתן
להעלות ככה, ולכן החלפה שלו נעשית משורת הפקודה:

```bash
git add model.tar.gz
git commit -m "new model"
git push
```

קובץ `.nojekyll` שיושב בריפו מבקש מ-Pages להגיש את הקבצים כמו שהם,
בלי מנוע Jekyll שמסתיר קבצים שמתחילים בקו תחתון.

### AI Studio — נוח לשיתוף, אבל לא לכיתה

`server.js` ו-`package.json` קיימים רק בשביל המסלול הזה: AI Studio מפרסם
את האפליקציה כשרת Node על Cloud Run, ולא כאתר סטטי. `server.js` מאזין
ל-`process.env.PORT` ונופל חזרה ל-3000, כי Cloud Run מזריק את הפורט בעצמו
ושרת שמאזין לפורט קבוע לא יעלה שם.

זה טוב לשלוח קישור ולהראות למישהו. **לפני שמסתמכים על זה בכיתה יש לבדוק
שני דברים**, ששניהם נוגעים בדיוק בלב האפליקציה — העבודה ללא אינטרנט:

- החלון בתוך AI Studio הוא iframe מאתר אחר. דפדפנים מפרידים אחסון לפי
  אתר, וחלקם חוסמים Service Worker ב-iframe כזה לגמרי. מה שצריך לבדוק זה
  הקישור הישיר לאפליקציה שפורסמה, לא התצוגה בתוך AI Studio.
- יש דיווחים שצנרת הפרסום של AI Studio מחליפה את ה-Service Worker של
  האפליקציה באחד משלה. לא אימתנו את זה מול תיעוד רשמי, אבל אם האפליקציה
  לא עולה במצב טיסה אחרי שכבר הורידה את המודל — זו הסיבה הראשונה לבדוק.

ב-GitHub Pages שתי השאלות האלה לא קיימות: הקבצים מוגשים כמו שהם, מאתר
משל עצמם, וה-Service Worker הוא זה שבריפו.

## המילים

16 מילים מוכנות, והמילה הבאה נבחרת בהגרלה — גם הראשונה כשפותחים. אין סדר
קבוע. הדבר היחיד שנמנע הוא אותה מילה פעמיים ברצף, כי זה נראה כמו תקלה ולא
כמו הגרלה. מעבר לזה זו הגרלה לכל דבר: מילה אחת יכולה לחזור פעמיים בתוך
עשר, ואחרת להיעדר קצת יותר.

כפתור **אוצר המילים** פותח חלונית ניהול: מוסיפים תמונה מהקטלוג, מוחקים,
ומאפסים לברירת המחדל. לחיצה על מילה קופצת אליה וסוגרת את החלונית. אין
סידור ידני, כי הסדר ברשימה לא משפיע על סדר התרגול. השם באנגלית קבוע לפי
האימוג'י — אין הקלדה. נשמר בדפדפן של המכשיר.

לשינוי הרשימה הקבועה לכולם — עורכים את `DEFAULT_WORDS` ב-`index.html`.
המילון של המודל מכיל כ-152,000 מילים באנגלית.

## בכיתה

פתיחה ראשונה עם אינטרנט מורידה את המודל, פעם אחת, עם פס התקדמות.
בזמן ההורדה 🔊 ו-⏭️ כבר עובדים — רק המיקרופון מחכה.
אחר כך "הוסף למסך הבית", ועובד גם בלי רשת. ההקלטות לא יוצאות מהמכשיר.

הקריינית מדברת עברית: "כל הכבוד!" בהצלחה, "נסו שוב" בכישלון. המילה
שמתרגלים נאמרת באנגלית, כמובן. אם במכשיר אין קול עברי מותקן (יש ב-iPhone
ובאנדרואיד; בכרום על דסקטופ לפעמים אין) המשוב הקולי פשוט שותק, במקום
שהדפדפן יקריא עברית בקול אנגלי. הצבע, ה-🎉 והכוכבים עובדים בכל מקרה.

רעש רקע, נשימה או "אממ" לא נחשבים ניסיון: המיקרופון ממשיך להקשיב עד
שנשמעת מילה מהרשימה או עד שעוברות 4 שניות. בין ניסיונות המנוע לא מעבד
אודיו בכלל, כדי לחסוך סוללה.

הדף גם מבקש מהדפדפן לשמור על המטמון כשנגמר מקום (`storage.persist`);
ב-Chrome זה מאושר אוטומטית אחרי "הוסף למסך הבית".
בלי רשת הדף והמודל עולים מהמטמון מיד. אם ה-WiFi מחובר אבל אין אינטרנט,
הדף מחכה לרשת עד 3 שניות ואז עולה מהמטמון.

את פס ההתקדמות אי אפשר לקבל מהמנוע — הוא לא מדווח כמה ירד — ולכן הדף
מוריד את `model.tar.gz` בעצמו ומניח אותו במטמון, והמנוע לוקח אותו משם.
מכאן ששם המטמון ב-`index.html` וב-`sw.js` חייב להישאר זהה.

## בדיקה מקומית

שתי דרכים, שתיהן עובדות:

```bash
python3 -m http.server 8000      # בלי להתקין כלום
```

```bash
npm install && npm run dev       # אותו שרת שרץ בפרסום, על פורט 3000
```

ואז http://localhost:8000 (או 3000) — לא בלחיצה כפולה על הקובץ,
המיקרופון חסום ב-file://

## מה עוד חסר

אין `manifest.json`. בלי הקובץ הזה "הוסף למסך הבית" באנדרואיד יוצר
קיצור דרך ולא התקנה אמיתית: אין אייקון משלנו, אין מסך פתיחה, והדף נפתח
עם סרגל הכתובות של הדפדפן. באייפון `apple-mobile-web-app-capable` כבר
מכסה את רוב זה. הזיהוי, המטמון והעבודה ללא אינטרנט לא תלויים בו.
